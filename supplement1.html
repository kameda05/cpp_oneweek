例外とは

エラーを知らせる方法

プログラムの実行中には、「0で割ろうとした」「存在しないファイルを開こうとした」「配列の範囲外にアクセスした」など、想定外のことが起こります。C言語では、このようなエラーを関数の戻り値で知らせるのが一般的でした。たとえば、失敗したら -1 や NULL を返す、といった方法です。

しかし、この方法には問題があります。戻り値を確認し忘れるとエラーに気づけませんし、本来の計算結果とエラーを同じ戻り値で表さなければならないこともあります。また、関数の呼び出しが何段にも重なっていると、エラーを一段ずつ呼び出し元へ返していく必要があり、プログラムが複雑になります。

例外処理

そこで C++ には、例外処理という仕組みが用意されています。エラーが起きた場所で例外を投げ（throw）、それを、エラーに対処できる場所で受け取る（catch）という考え方です。例外が投げられると、それ以降の処理は飛ばされ、例外を受け取る場所まで処理が一気に移ります。

例外の基本

サンプルプログラム

まずは、0で割ろうとしたときに例外を投げるプログラムを見てみましょう。

lists1-1：main.cpp
#include <iostream>
#include <stdexcept>

using namespace std;

//    割り算をする関数（0で割ろうとしたら例外を投げる）
double divide(int a, int b){
    if (b == 0){
        throw runtime_error("0で割ることはできません");
    }
    return static_cast<double>(a) / b;
}

int main(){
    try {
        cout << divide(10, 4) << endl;
        cout << divide(5, 0) << endl;
        cout << "この行は実行されません" << endl;
    }
    catch (const runtime_error& e) {
        cout << "エラー：" << e.what() << endl;
    }
    cout << "プログラムを終了します" << endl;
    return 0;
}
実行結果
2.5
エラー：0で割ることはできません
プログラムを終了します

throw：例外を投げる

関数 divide() の中の9行目で、割る数 b が 0 のときに例外を投げています。例外を投げるには throw を使います。

例外を投げる
throw 例外オブジェクト;

ここでは、標準ライブラリに用意されている runtime_error クラスのオブジェクトを、エラーの説明文を付けて投げています。runtime_error を使うには、ヘッダ stdexcept をインクルードします（2行目）。

try と catch：例外を受け取る

例外が投げられる可能性のある処理は、try ブロックの中に書きます。その直後に catch ブロックを書き、受け取る例外の型と、例外が起きたときの処理を記述します。

try と catch
try {
例外が投げられる可能性のある処理
}
catch (例外の型 変数名) {
例外が起きたときの処理
}

16行目の divide(10, 4) は正常に計算され、2.5 が表示されます。一方、17行目の divide(5, 0) では例外が投げられるため、処理はすぐに20行目の catch ブロックへ移ります。そのため、18行目は実行されません。catch ブロックの処理が終わると、try〜catch の後ろ（23行目）から処理が続きます。

受け取った例外オブジェクトの what() メンバ関数を呼び出すと、例外を投げたときに渡した説明文を取り出せます。

💡 catch では、例外を const runtime_error& e のように const 参照で受け取るのが基本です。値で受け取るとオブジェクトのコピーが作られるうえ、子クラスの例外を親クラスの型で受け取ったときに、子クラスの情報が失われてしまいます。

例外が受け取られなかった場合

投げられた例外をどこでも受け取らなかった場合、プログラムはその時点で強制終了します。例外が投げられる可能性がある処理は、必ずどこかで受け取るようにしましょう。

標準の例外クラス

例外クラスの種類

C++ の標準ライブラリには、エラーの種類に応じた例外クラスが用意されています。いずれも exception クラスを親とする継承関係にあります（表S1-1）。

表S1-1：主な標準の例外クラス
クラス名親クラス意味
exceptionなしすべての標準の例外クラスの親クラス
logic_errorexceptionプログラムの論理的な誤り
invalid_argumentlogic_error関数に不正な引数が渡された
out_of_rangelogic_error範囲外の値やインデックスが使われた
runtime_errorexception実行してみないとわからないエラー
bad_allocexceptionnew でメモリを確保できなかった

標準ライブラリが投げる例外

標準ライブラリの関数の中にも、エラーのときに例外を投げるものがあります。次のサンプルを実行してみてください。

lists1-2：main.cpp
#include <iostream>
#include <string>
#include <vector>
#include <stdexcept>

using namespace std;

int main(){
    vector<int> v;
    v.push_back(10);
    v.push_back(20);
    v.push_back(30);
    //    範囲外の要素へのアクセス
    try {
        int a = v.at(1);
        cout << "v.at(1) = " << a << endl;
        int b = v.at(5);
        cout << "v.at(5) = " << b << endl;
    }
    catch (const out_of_range& e) {
        cout << "範囲外のアクセス：" << e.what() << endl;
    }
    //    数値に変換できない文字列
    try {
        int n = stoi("123");
        cout << "n = " << n << endl;
        int m = stoi("abc");
        cout << "m = " << m << endl;
    }
    catch (const invalid_argument& e) {
        cout << "数値に変換できません：" << e.what() << endl;
    }
    catch (const exception& e) {
        cout << "その他の例外：" << e.what() << endl;
    }
    return 0;
}
実行結果
v.at(1) = 20
範囲外のアクセス：invalid vector subscript
n = 123
数値に変換できません：invalid stoi argument

vector の at() メンバ関数は、[] と同じように要素を取り出しますが、範囲外のインデックスを指定すると out_of_range を投げます。[] の場合は範囲のチェックをしないため、範囲外にアクセスしても例外は投げられず、プログラムが予期しない動きをします。

stoi() は、文字列を int 型の整数に変換する関数です。"abc" のように数値として読めない文字列を渡すと、invalid_argument を投げます。

⚠️ what() が返す説明文の内容は、コンパイラによって異なります。実行結果は Visual Studio の場合の例です。

複数の catch

2つ目の try ブロックのように、catch ブロックは複数並べることができます。例外は、上から順に型が合うかどうかを調べられ、最初に合った catch ブロックで受け取られます。

親クラスの型の catch は、子クラスの例外も受け取ります。そのため、catch (const exception& e) は、標準の例外をすべて受け取ることができます。このような親クラスの catch は、子クラスの catch より後ろに書くようにしましょう。前に書くと、すべての例外がそこで受け取られてしまい、後ろの catch が使われなくなります。

独自の例外クラス

サンプルプログラム

標準の例外クラスを継承すれば、独自の例外クラスを作ることもできます。次のサンプルは、銀行口座から残高より多い金額を引き出そうとしたときに、独自の例外を投げるものです。

lists1-3：main.cpp
#include <iostream>
#include <string>
#include <stdexcept>

using namespace std;

//    残高不足を表す例外クラス
class InsufficientFunds : public runtime_error{
private:
    int m_shortage;    //    不足している金額
public:
    InsufficientFunds(int shortage)
        : runtime_error("残高が不足しています"), m_shortage(shortage){}
    int getShortage() const { return m_shortage; }
};

//    銀行口座クラス
class BankAccount{
private:
    int m_balance;    //    残高
public:
    BankAccount(int balance) : m_balance(balance){}
    //    お金を引き出す
    void withdraw(int amount){
        if (amount > m_balance){
            throw InsufficientFunds(amount - m_balance);
        }
        m_balance -= amount;
    }
    int getBalance() const { return m_balance; }
};

int main(){
    BankAccount account(1000);
    try {
        account.withdraw(300);
        cout << "残高：" << account.getBalance() << "円" << endl;
        account.withdraw(1500);
        cout << "残高：" << account.getBalance() << "円" << endl;
    }
    catch (const InsufficientFunds& e) {
        cout << e.what() << "（不足額：" << e.getShortage() << "円）" << endl;
    }
    return 0;
}
実行結果
残高：700円
残高が不足しています（不足額：800円）

例外クラスの作り方

InsufficientFunds クラスは、runtime_error を継承した例外クラスです（8行目）。コンストラクタでは、親クラス runtime_error のコンストラクタに説明文を渡しています（13行目）。こうしておくと、what() でその説明文を取り出せます。

さらに、不足している金額をメンバ変数 m_shortage に記録し、getShortage() で取り出せるようにしています。このように、エラーの詳しい情報を例外オブジェクトに持たせられるのが、独自の例外クラスを作る利点です。

BankAccount クラスの withdraw() は、残高が足りないときに InsufficientFunds を投げます（26行目）。main() では、その例外を受け取って、説明文と不足額を表示しています。

例外とデストラクタ

サンプルプログラム

例外が投げられて処理が飛んだとき、それまでに作られていたオブジェクトはどうなるのでしょうか。次のサンプルで確かめてみましょう。

lists1-4：main.cpp
#include <iostream>
#include <string>
#include <stdexcept>

using namespace std;

//    生成と消去を表示するだけのクラス
class Logger{
private:
    string m_name;
public:
    Logger(string name) : m_name(name){
        cout << m_name << "：コンストラクタ" << endl;
    }
    ~Logger(){
        cout << m_name << "：デストラクタ" << endl;
    }
};

void func(){
    Logger lg("func内のオブジェクト");
    throw runtime_error("func()で例外が発生");
}

int main(){
    try {
        Logger lg("try内のオブジェクト");
        func();
    }
    catch (const exception& e) {
        cout << "例外を受け取りました：" << e.what() << endl;
    }
    return 0;
}
実行結果
try内のオブジェクト：コンストラクタ
func内のオブジェクト：コンストラクタ
func内のオブジェクト：デストラクタ
try内のオブジェクト：デストラクタ
例外を受け取りました：func()で例外が発生

スタックの巻き戻し

実行結果を見ると、func() の中で例外が投げられたあと、catch ブロックの処理が始まる前に、func() の中のオブジェクトと、try ブロックの中のオブジェクトのデストラクタが、作られたのと逆の順に呼ばれていることがわかります。

このように、例外によって関数やブロックを抜けるときにも、その中で作られたオブジェクトのデストラクタは必ず呼ばれます。これをスタックの巻き戻しと言います。

この性質を利用すると、「デストラクタで後始末をするクラス」を使うことで、例外が起きても確実にメモリの解放やファイルのクローズを行えます。この考え方は RAII と呼ばれ、C++ のプログラミングでとても重要です。補講2で扱うファイルのクラスも、このしくみでファイルを自動的に閉じています。

⚠️ 一方、new で確保したメモリは、スタックの巻き戻しでは解放されません。new の後、delete までの間で例外が起きると、メモリが解放されずに残ってしまいます。このような問題を防ぐ方法は、モダンC++のスマートポインタで学びます。

例外を使ううえでの注意

  • 例外は、本当に例外的な状況（めったに起きないエラー）に使います。通常の処理の分岐に使うと、プログラムがわかりにくくなります。
  • デストラクタの中から例外を投げてはいけません。スタックの巻き戻しの最中にさらに例外が投げられると、プログラムは強制終了します。
  • catch (...) と書くと、どんな型の例外でも受け取れます。ただし、どんな例外かを調べられないので、使う場面は限られます。
